## Защита уязвимого PHP-приложения

### Цель работы

Найти и исправить основные уязвимости в готовом веб-приложении.

### Задание

Необходимо:

1. Защитить SQL-запросы с помощью prepared statements.
2. Реализовать безопасное хранение и проверку паролей.
3. Добавить серверную валидацию входных данных.
4. Защитить вывод пользовательских данных от XSS.
5. Исправить контроль доступа к заметкам и административной странице.
6. Защитить операции изменения и удаления данных от CSRF.
7. Улучшить создание, проверку и завершение пользовательской сессии.
8. Скрыть технические детали ошибок от пользователя.
9. Добавить журналирование важных действий и ошибок.
10. Закрыть публичный доступ к служебным файлам.

### Отчёт

Подготовьте отчёт в формате Word или PDF. Для каждой найденной проблемы укажите:

К работе приложите исходный код защищённой версии и обновлённый SQL-файл, если структура базы данных была изменена.

## Исправленные уязвимости
 
### 1. SQL-инъекции (SQL Injection)
**Было:** Прямое конкатенирование переменных в SQL-запросы.
```php
$pdo->query("SELECT * FROM notes WHERE id = $id")
```
**Исправлено:** Prepared statements везде.
```php
$stmt = $pdo->prepare("SELECT * FROM notes WHERE id = ?");
$stmt->execute([$id]);
```
 
### 2. Небезопасное хранение паролей
**Было:** Пароли в открытом виде в БД.
**Исправлено:** Хеширование с `password_hash()` и проверка с `password_verify()`.
 
### 3. XSS (Cross-Site Scripting)
**Было:** Прямой вывод пользовательских данных.
```php
<?= $note['content'] ?>
```
**Исправлено:** Экранирование всего пользовательского контента.
```php
<?= nl2br(e($note['content'])) ?>
```
 
### 4. IDOR (Insecure Direct Object Reference)
**Было:** Редактирование/удаление заметок без проверки принадлежности.
```php
$pdo->exec("DELETE FROM notes WHERE id = $id")
```
**Исправлено:** Проверка `user_id` в каждом запросе.
```php
$stmt = $pdo->prepare("DELETE FROM notes WHERE id = ? AND user_id = ?");
$stmt->execute([$id, $userId]);
```
 
### 5. CSRF (Cross-Site Request Forgery)
**Было:** Удаление и выход без защиты от CSRF.
**Исправлено:** CSRF токены в формах, проверка с `hash_equals()`.
 
### 6. Отсутствие контроля доступа
**Было:** Страница админа доступна любому пользователю.
**Исправлено:** `require_admin()` функция с проверкой роли.
 
### 7. Небезопасное управление сессией
**Было:** Нет `session_regenerate_id()` после логина.
**Исправлено:** 
- Регенерация ID после аутентификации.
- httponly + samesite флаги для cookies.
- Timeout 30 минут неактивности.
- Правильное очищение сессии при выходе.
### 8. Утечка технической информации
**Было:** SQL ошибки и детали реализации видны пользователю.
```php
die('Заметка не найдена. SQL: SELECT * FROM notes WHERE id = ' . $id);
```
**Исправлено:** Обобщённые сообщения пользователю, детали в логи.
 
### 9. Отсутствие логирования
**Было:** Нет записей о действиях пользователей.
**Исправлено:** `log_event()` логирует все критические события.
 
### 10. Публичный доступ к служебным файлам
**Было:** Можно скачать `database.sql`, `config.php`, `.md` файлы.
**Исправлено:** `.htaccess` блокирует доступ.
 
## Тестирование
 
### 1. SQL-инъекция
- **Было:** Попробуйте `' OR '1'='1` в email на логине → доступ без пароля.
- **Исправлено:** Попробуйте то же → "Пользователь не найден или пароль неправильный."
### 2. XSS
- **Было:** Добавьте заметку с `<script>alert('XSS')</script>` → скрипт выполняется.
- **Исправлено:** Текст экранируется → `<script>` видно как текст.
### 3. IDOR
- **Было:** Отредактируйте URL от `/edit_note.php?id=2` на `id=1` → редактируете чужую заметку.
- **Исправлено:** Попытка → "Заметка не найдена." (проверка user_id).
### 4. Контроль доступа
- **Было:** Зайдите обычным пользователем, откройте `/admin.php` → видите список пользователей и пароли.
- **Исправлено:** Откройте `/admin.php` → "Access denied." (require_admin).
### 5. CSRF
- **Было:** Запрос на удаление через GET → `/delete_note.php?id=1` → заметка удаляется.
- **Исправлено:** DELETE это POST форма → без CSRF токена ничего не удалится.
### 6. Пароли
- **Было:** Откройте `/admin.php` (если бы был доступ) → видны пароли в открытом виде.
- **Исправлено:** Пароли хешированы, открытые данные недоступны.
### 7. Сессия
- **Было:** После входа session_id не меняется.
- **Исправлено:** `session_regenerate_id(true)` после аутентификации.
### 8. Логирование
- Проверьте файл `/logs/activity.log` (за пределами веб-корня):
```
  [2026-10-19 14:32:15] User:1 IP:127.0.0.1 Type:login_success Details:Email: admin@example.local
  [2026-10-19 14:33:22] User:1 IP:127.0.0.1 Type:note_created Details:Title: Тестовая заметка
  [2026-10-19 14:34:10] User:1 IP:127.0.0.1 Type:logout Details:User logged out
```
 
### 9. Защита файлов
- **Было:** Откройте `/config.php` → видите параметры БД.
- **Исправлено:** Откройте `/config.php` → 403 Forbidden (`.htaccess`).
### 10. Ошибки
- **Было:** При ошибке в БД видно SQL и исключение.
- **Исправлено:** Пользователь видит "Ошибка при создании заметки.", детали в логи.
## Дополнительные улучшения
 
- **Валидация входных данных:** длина имени, email формат, длина пароля.
- **Таймаут сессии:** автоматический выход после 30 минут неактивности.
- **Логирование:** всех попыток входа, создания/редактирования/удаления заметок, ошибок.
- **Безопасные заголовки:** httponly cookies, samesite=Lax.
- **Обобщённые ошибки:** пользователь не узнаёт детали реализации.
